MKI Password Policy

Installing the plugin changes nothing about sign-ins or passwords. Rules only apply to users you assign a profile to, and a password change is only required when you ask for one. It is then enforced on the server, so it holds on every client: browser, phone, TV, Quick Connect and all apps.
Every change on this page takes effect immediately. There is nothing to save; anything that signs people out or locks accounts asks first.

Rules

Applies to every user set to “Same as all users” below and to newly created accounts. “No rules” means the plugin checks nothing.

Overview

The plugin never stores passwords and never judges a stored password after the fact; Jellyfin itself only keeps a hash. A password is checked only at the moment it is set. After that the plugin only remembers which rules it was checked against. That is why passwords set before then honestly show “Unknown”.

“Temporary password” creates a random password, shows it to you once and signs the user out everywhere. The user signs in with it and must then choose their own. Use it for forgotten passwords and for accounts without a password, which stay locked until they get one.

Require a new password

Accounts without any password never get a notice period: once they have a profile or a request, they are locked right away on every app, TV and Quick Connect, and only a temporary password from you unlocks them. Nobody can claim such an account by just knowing its name.

Link for TVs and apps

In a browser and in the Jellyfin apps for Android, iOS and desktop, users get a popup they have to answer, and the change dialog right at sign-in. TVs and other apps show Jellyfin’s own message window while the user still has access (during a notice period), and after that only “sign-in failed”. Those users set their password through this link, for example on their phone, and then sign in as usual.
